# Прогноз вероятности роста цены акций (Мосбиржа)

Научно-исследовательская работа по технологиям машинного обучения: оценка **вероятности** того, что в течение заданного горизонта **дневное закрытие** акции **хотя бы раз превысит** текущее закрытие. Данные — дневные свечи с **информационно-статистического сервера (ISS)** ПАО Московская Биржа.

Основной код и эксперименты: Jupyter-ноутбук [`1.ipynb`](1.ipynb). Справочник по API биржи: [`Документация.txt`](Документация.txt).

## Цель и постановка задачи

- **Классификация** (бинарная): для каждой пары «тикер — торговый день» по истории до этого дня предсказывается вероятность события.
- **Событие (таргет `y_hit_within`)**: среди цен **закрытия** следующих `HORIZON_TRADING_DAYS` торговых сессий (по умолчанию **21**, условный «месяц») существует день, в который `close` **строго выше**, чем `close` в текущий день.
- Выход модели для последней доступной точки по каждому тикеру: колонка **`p_hit_within_month`** (калиброванная вероятность).

Исследовательский характер: модель **не является** торговой рекомендацией и не учитывает комиссии, проскальзывание, ликвидность и внешние новости.

## Источник данных

- Запросы к ISS по протоколу HTTP(S), формат JSON.
- Пример эндпоинта для дневных свечей акции:  
  `https://iss.moex.com/iss/engines/stock/markets/shares/securities/{SECID}/candles.json`  
  с параметрами периода (`from`, `till`), `interval=24` (дневные свечи), пагинация через `start`.
- Подробности запросов, блоков данных и системных параметров (`iss.only`, `iss.meta` и др.) — в [`Документация.txt`](Документация.txt).

## Используемые инструменты

- **Python 3** (в ноутбуке указана 3.11.x).
- **pandas**, **numpy**, **requests**, **matplotlib** — данные и визуализация.
- **scikit-learn**: `Pipeline`, `CalibratedClassifierCV`, `HistGradientBoostingClassifier`, метрики качества.

## Датасет

- **Тикеры** (ликвидные акции, множество бумаг в одной выборке): SBER, GAZP, LKOH, GMKN, ROSN, NVTK, TATN, MGNT, ALRS, VTBR (список задаётся в ноутбуке).
- **Глубина истории**: по умолчанию около **трёх лет** до текущей даты.
- **Кодирование тикера**: one-hot (`pd.get_dummies` по `secid`) как дополнительные признаки.

## Признаки

Для каждого дня и тикера (после прогрева окон, для MA200 нужно ≥200 торговых дней истории):

- доходности `close` за 1, 2 и 5 дней;
- относительный спред high–low к `close`, отношение (close − open) / open;
- объём: дневное изменение и отношение к медиане за 20 дней;
- MA5/MA20, положение цены относительно MA50 и MA200;
- RSI(14), отношение ATR(14) к `close`, отношение волатильностей 5/20 дней;
- день недели (`dow`);
- **относительная доходность** `rel_ret1` = доходность акции − доходность индекса **IMOEX** (дневные свечи с рынка `index`).

Перед расчётом признаков OHLC **нормализуются по каждому тикеру**: деление на SMA(`close`, 20) (типичный уровень ~1.0 у SBER, GAZP, LKOH и т.д.). Таргеты (`y_hit_within`, просадка) считаются по **сырым** ценам в рублях.

Пропуски и бесконечности после расчётов отбрасываются; в пайплайне — `SimpleImputer`.

## Модель и валидация

- **Логистическая регрессия** и **HistGradientBoosting** (`class_weight="balanced"`) в `Pipeline` с имputation (и scaler для логрега).
- **`CalibratedClassifierCV`** (isotonic, `TimeSeriesSplit`) — калибровка вероятностей на обучающей выборке.
- **Разделение train / test по календарным датам**: первые 80% уникальных торговых дат — обучение, остальные 20% — тест; все тикеры за один день целиком в одной части.
- В ноутбуке: сравнение моделей по AUC / Brier / balanced accuracy и **reliability diagram** на тесте.

## Метрики

- **ROC-AUC** — качество ранжирования независимо от порога 0.5.
- **Brier score** — ошибка вероятностного прогноза.
- **Accuracy** при сильном дисбалансе классов (для «месячного» события доля положительного класса часто высокая) может быть **высокой у наивного правила**; в ноутбуке выводится предупреждение смотреть на AUC и Brier.

## Ограничения и возможное развитие

- Прогноз опирается только на **прошлые OHLCV**; макроэкономика, отчётность, новости и микроструктура рынка не моделируются.
- Горизонт задан в **торговых днях**, а не в календарных.
- **Модель рискованности** (§6): таргет `y_high_risk` — просадка ≥ `RISK_DRAWDOWN_PCT` за 21 торговый день; выход `p_high_risk`.
- **Прогноз роста в %** (§7): регрессия на `max_upside_pct` — на сколько % максимальное закрытие за горизонт превысит текущее; выход `pred_max_upside_pct`.
- **Сводка** (§8): `p_hit_within_month`, `p_high_risk`, `pred_max_upside_pct`.
- Дальше — walk-forward валидация, внутридневные данные, отчётность эмитентов.
